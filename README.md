# Remote Diagnostics System

A Linux-based **Remote Diagnostics and Process Management System** developed using C programming and TCP socket programming.

This project allows users to monitor and manage processes running on a remote Linux machine through a command-line client. It provides information about process status, CPU and memory utilization, network connections, and open file descriptors.

The project demonstrates practical applications of Linux system programming, network programming, process management, and terminal handling.

## Project Overview

In real-world environments, system administrators and support engineers often need to investigate processes running on remote systems.

This project provides a simple client-server solution for performing such diagnostic operations remotely.

### How It Works

1. The diagnostic server runs on the Linux machine that needs to be monitored.
2. The client establishes a TCP connection with the server using its IP address and port number.
3. The client sends diagnostic requests to the server.
4. The server processes the requests using Linux system utilities and interfaces.
5. The server sends the requested diagnostic information back to the client.
6. The client displays the received information.

## Features

### 1. Process Monitoring
- Retrieve the list of currently running processes.
- Identify processes using their Process IDs (PIDs).
- Inspect individual process information.

### 2. Resource Monitoring
- Monitor CPU utilization of a specific process.
- Retrieve memory usage information.
- Display resident and virtual memory sizes.

### 3. Network Diagnostics
- Identify TCP and UDP connections associated with a process.
- Inspect network ports used by a process.
- Retrieve socket information using `lsof`.

### 4. File Descriptor Inspection
- List open file descriptors associated with a process.
- Inspect files, sockets, and other resources opened by a process.

### 5. Remote Process Management
- Terminate a selected process remotely using its PID.
- Validate process IDs before performing operations.

### 6. Interactive Command-Line Interface
- Interactive client-side command prompt.
- Command history management.
- Up and Down arrow-key navigation.
- Reuse previously entered commands without typing them again.

### 7. Terminal Input Handling
- Uses Linux terminal control APIs (`termios`).
- Implements non-canonical terminal input handling.
- Reads keyboard input character by character.
- Handles escape sequences generated by arrow keys.

## Command History and Arrow-Key Operations

The client provides command history functionality to improve the command-line experience.

Instead of manually entering previously executed commands, users can navigate through command history using the keyboard.

| Key | Operation |
|---|---|
| Up Arrow (↑) | Displays the previously entered command |
| Down Arrow (↓) | Navigates towards the next command in history |

**Example:**

Suppose the user previously entered:

```text
Client] get-processes ALL
Client] get-mem 1234
Client] get-cpu-usage 1234
```

Pressing the Up Arrow repeatedly navigates through these commands in reverse order.

Pressing the Down Arrow moves forward through the command history.

This functionality is implemented using terminal input handling and escape-sequence detection.

## Available Commands

| Command | Description |
|---|---|
| `get-processes ALL` | Displays currently running processes |
| `get-mem <PID>` | Displays memory usage of a process |
| `get-cpu-usage <PID>` | Displays CPU utilization of a process |
| `get-ports-used <PID>` | Displays network ports and sockets used by a process |
| `get-open-fd <PID>` | Displays open file descriptors of a process |
| `kill <PID>` | Terminates the specified process |

Replace `<PID>` with the actual Process ID.

### Example

```text
Client] get-processes ALL

Client] get-mem 1234

Client] get-cpu-usage 1234

Client] get-ports-used 1234

Client] get-open-fd 1234

Client] kill 1234
```

## Prerequisites

- Linux operating system
- GCC compiler
- GNU Make
- `lsof` utility

Install the required packages on Ubuntu:

```bash
sudo apt update
sudo apt install build-essential lsof
```

## Build Instructions

Clone the repository:

```bash
git clone https://github.com/pathakuntalokeswarreddy/LI_4_Remote_Disgnostics.git
```

Navigate to the project directory:

```bash
cd LI_4_Remote_Disgnostics
```

Compile the project:

```bash
make
```

After successful compilation, the following executables are generated:

```text
bin/server
bin/client
```

To remove the generated executables:

```bash
make clean
```

## Running the Application

### Step 1: Start the Server

Run the server on the Linux machine that needs to be monitored.

```bash
./bin/server <port>
```

Example:

```bash
./bin/server 5000
```

The server starts listening for incoming TCP connections.

### Step 2: Start the Client

Run the client from another terminal or machine.

```bash
./bin/client <server-ip> <port>
```

Example:

```bash
./bin/client 192.168.0.119 5000
```

Once the connection is established, the client displays an interactive command prompt.

### Step 3: Execute Diagnostic Commands

Enter the required diagnostic command at the client prompt.

For example:

```text
Client] get-processes ALL
```

The client sends the request to the server, and the server returns the corresponding process information.
